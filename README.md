# Komori Launcher 0.6.0

Лаунчер Minecraft для Windows в стиле Komori. Electron, без сторонних библиотек для Minecraft: версии, Java и ассеты качаются напрямую с серверов Mojang.

## Новое в 0.6.0: тема и ссылки

**Тема.** Настройки → Общие → «Тема»: Светлая, Тёмная или Системная. «Системная» следит за темой Windows на лету. Выбор хранится в `settings.json` (`theme`). Главный экран с артом остаётся тёмным в любой теме.

**Discord, сайт, соцсети.** Всё задаётся в `komori.config.json`, пустые поля скрывают кнопки:
```json
"discordUrl": "https://discord.gg/xxxx",
"websiteUrl": "https://komori.fun",
"socialLinks": [
  { "name": "Telegram", "url": "https://t.me/komori", "icon": "telegram" },
  { "name": "YouTube", "url": "https://youtube.com/@komori", "icon": "youtube" },
  { "name": "VK", "url": "https://vk.com/komori", "icon": "vk" },
  { "name": "X", "url": "https://x.com/komori", "icon": "x" }
]
```
Discord и «Сайт» — кнопки внизу боковой панели. Соцсети — иконки на главной и блок «Соцсети» в настройках. Иконки лежат в `src/renderer/icons/`: telegram, youtube, vk, x, discord, globe, link, twitch, tiktok, instagram (неизвестное имя → link). Принимаются только https-ссылки, открывает их main-процесс в браузере по умолчанию.

## Скины офлайн-аккаунтов (0.6.0)

Настройки → Аккаунт: у офлайн-аккаунта можно загрузить PNG 64×64 (или 64×32), выбрать модель рук и посмотреть превью спереди, сзади, сбоку и развёртку. Скин хранится в `<данные лаунчера>/skins/<uuid>.png`.

Чтобы скин видели другие игроки Komori Launcher, нужен сервер скинов — Cloudflare Worker из папки `skin-server/` (инструкция там). Его адрес вписывается в `komori.config.json` → `skinServerUrl` (или в Настройки → Общие → «URL сервера скинов»). При запуске игры офлайн-аккаунтом лаунчер скачивает authlib-injector (один раз, с официального сайта, с проверкой SHA-256) и подключает его — работает на любой версии и сборке, включая ваниллу, моды не нужны. Microsoft-аккаунты это не затрагивает.

## Новое в 0.5.0: автообновление и отчёт о вылете

### Автообновление
Лаунчер сам проверяет GitHub Releases (`k1opy/komori-launcher`) через 4 секунды после старта и потом каждые 4 часа. Новая версия скачивается в фоне. Когда она готова, в боковой панели появляется кнопка «Перезапустить». Пока запущена игра, обновление не ставится. DEV-сборка и `npm run dev` не обновляются.

Как выпустить версию:
1. Поднять `version` в `package.json`, например до `0.5.1`.
2. Создать токен GitHub (Settings → Developer settings → Fine-grained token, доступ Contents: Read and write к репозиторию).
3. В CMD: `set GH_TOKEN=токен`, затем `npm run release`.
4. На GitHub в Releases опубликовать созданный черновик (Draft → Publish).

Без токена: `npm run dist`, затем создать релиз с тегом `v0.5.1` и вручную загрузить из `dist\` три файла: `Komori-Launcher-Setup-0.5.1.exe`, `.exe.blockmap` и `latest.yml`. Без `latest.yml` обновление не увидит новую версию.

### Отчёт о вылете
Если игра закрылась с ошибкой, лаунчер показывает окно с причиной (строка `Description` и исключение из crash-report). Игрок может добавить комментарий и нажать «Отправить админам». В Discord уйдут: crash-report, `latest.log`, лог запуска, список модов, ник, версия, загрузчик и Java. Отправлять можно раз в минуту.

Настройка: создать вебхук в отдельном закрытом канале Discord (Настройки канала → Интеграции → Вебхуки) и вставить ссылку в `komori.config.json` → `crashWebhookUrl`. Если поле пустое, кнопка отправки скрыта, а «Открыть лог» работает.

После обновления до 0.5.0 нужно один раз выполнить `npm install`: добавилась зависимость `electron-updater`.

## Новое в 0.4.0: сборка сервера для «Играть на Komori»
Админы задают, с какой версией, ядром и модами игроки заходят на сервер. Игроки ничего не настраивают.

**Как это работает у игрока.** «Играть на Komori» скачивает файл сборки `komori-server.json`, создаёт или обновляет профиль «Сервер»,
ставит версию и ядро, докачивает недостающие моды, удаляет снятые админом, включает обратно выключенные обязательные и заходит на сервер.
Свои моды игрока в папке профиля не трогаются. Профиль сервера нельзя редактировать в лаунчере — его задаёт сборка.

**Как обновить сборку (админ, DEV-сборка лаунчера).**
1. Настрой обычный профиль: версия, ядро, моды и ресурспаки из каталога Modrinth/CurseForge.
2. Настройки → «Сервер (админ)» → выбери профиль → «Собрать».
3. Проверь список. Моды, добавленные вручную или запрещённые автором для лаунчеров, в сборку не попадают — лаунчер покажет их отдельно.
4. «Сохранить komori-server.json» и загрузи файл на хостинг по ссылке из `serverManifestUrl`.
   У всех игроков сборка обновится при следующем «Играть на Komori».

**Настройка `komori.config.json`.**
- `serverManifestUrl` — https-ссылка на `komori-server.json` (сайт, GitHub raw и т. п.). Пустая — кнопка запускает выбранный профиль, как раньше.
- `trustedHosts` — свои сайты, откуда можно качать файлы сборки, например `["files.komori.fun"]`.
  Modrinth и CurseForge разрешены всегда. Так в сборку можно вручную вписать свои моды:
  `{ "path": "mods/komori-addon.jar", "url": "https://files.komori.fun/komori-addon.jar", "sha1": "…", "title": "Komori Addon" }`.
- Файлы сборки могут лежать только в `mods/`, `resourcepacks/`, `shaderpacks/`, `config/`, по https и с SHA-1.

## Новое в 0.3.0
- Каталог CurseForge рядом с Modrinth (переключатель на экране «Моды»): моды, ресурспаки, шейдеры, зависимости, обновления.
  Файлы, которые автор запретил качать в сторонних лаунчерах, не скачиваются в обход — лаунчер показывает список со ссылками.
- Сборки (модпаки) с Modrinth и CurseForge: вкладка «Сборки», кнопка «Установить сборку» создаёт новый профиль с нужным ядром и версией.
  «Импорт из файла» — для скачанных .mrpack и zip-сборок CurseForge.
- Скин и плащ для аккаунтов Microsoft: Настройки → Аккаунт. Загрузка PNG 64×64 (классические или тонкие руки), сброс, выбор плаща, превью.

## Ключ CurseForge
1. Зайди на console.curseforge.com, создай организацию и запроси ключ Core API (бесплатно).
2. Впиши ключ в `komori.config.json` → `curseforgeApiKey`.
Без ключа работает только Modrinth.

## Новое в 0.2.0
- Ядра Fabric, Quilt, Forge, NeoForge: выбор версии ядра в окне профиля («Авто» берёт рекомендуемую или стабильную).
  - Fabric и Quilt ставятся мгновенно (профиль с их серверов).
  - Forge и NeoForge ставятся официальным установщиком в тихом режиме, первый раз 1–3 минуты.
- Каталог Modrinth на экране «Моды»: поиск модов, ресурспаков и шейдеров, сортировка, «Показать ещё».
  Показывается только то, что подходит ядру и версии профиля. Обязательные зависимости (например, Fabric API) ставятся сами.
- Вкладка «Установленные»: всё из папок mods, resourcepacks, shaderpacks (в том числе положенное вручную),
  включение и выключение без удаления, удаление, проверка обновлений и «Обновить всё».
- Файлы с Modrinth проверяются по SHA-1 и качаются только с cdn.modrinth.com.

## Что работает
- Окно по макету: Главная, Профили, Версии, Моды, Настройки.
- Список всех версий Minecraft: релизы, снапшоты, бета и альфа, с поиском.
- Скачивание версии: клиент, библиотеки, нативные файлы, ресурсы (включая старые версии с особыми путями ресурсов).
- Автоматическая Java от Mojang под каждую версию (Java 8 для старых, 17, 21+ для новых).
- Профили: название, 26 иконок, версия (в том числе «всегда последний релиз или снапшот»), своя папка, своя память.
- Запуск игры, кнопка «Играть на Komori» (сразу подключает к mc.komori.fun на версиях, где это поддерживается).
- Вход через Microsoft (код на сайте Microsoft), смена ника Microsoft-аккаунта.
- DEV-вход по нику только в тестовой сборке.

## Ограничения
- Forge поддерживается для версий, где установщик умеет тихий режим (1.13 и новее; 1.12.2 — последние сборки).
- NeoForge — для 1.20.2 и новее.
- Сборка ставится в последней версии (выбор старой версии сборки — позже).

## Сборка (Windows, CMD)
1. Установи Node.js 20 LTS или новее с nodejs.org (галочка «Add to PATH»).
2. Распакуй архив в `C:\Users\Killer\Desktop\KomoriLauncher`.
3. Первый раз:
   ```
   cd /d C:\Users\Killer\Desktop\KomoriLauncher
   npm install
   ```
4. Запуск без сборки:
   - `npm run dev` — с DEV-входом (для тестов)
   - `npm start` — как у игроков, без DEV-входа
5. Установщик:
   - `npm run dist:dev` — тестовая сборка с DEV-входом → `dist\Komori-Launcher-DEV-Setup-0.1.0.exe`
   - `npm run dist` — обычная сборка для игроков → `dist\Komori-Launcher-Setup-0.1.0.exe`

DEV-вход есть только в `npm run dev` и в сборке `dist:dev`. В обычной сборке кнопки нет, и сам обработчик входа отказывает.

## Вход через Microsoft
1. portal.azure.com → «Регистрация приложений» → «Новая регистрация».
   Тип учётных записей: «Только личные учётные записи Майкрософт».
2. В приложении: «Проверка подлинности» → «Разрешить потоки общедоступных клиентов» → Да.
3. Скопируй «Идентификатор приложения (клиента)» в `komori.config.json` → `msClientId`.
4. Подай заявку на доступ к Minecraft API для этого ID (форма Microsoft: https://aka.ms/mce-reviewappid).
   Пока заявку не одобрят, вход дойдёт до последнего шага и покажет «Mojang пока не одобрил доступ».

## Где что лежит
- Игра: `%APPDATA%\.komori` (versions, libraries, assets, runtime с Java, instances с папками профилей).
- Настройки, профили и аккаунты: `%APPDATA%\Komori Launcher` (токены зашифрованы средствами Windows).
- Лог последнего запуска профиля: `instances\<профиль>\komori-launch.log`.

## Структура проекта
- `src/main/main.js` — окно и связь с интерфейсом
- `src/main/versions.js` — список и установка версий
- `src/main/java.js` — загрузка Java
- `src/main/launch.js` — аргументы и запуск
- `src/main/auth.js` — Microsoft и DEV-вход
- `src/main/loaders.js` — Fabric, Quilt, Forge, NeoForge
- `src/main/modrinth.js` — каталог Modrinth, установка, обновления
- `src/main/curseforge.js` — каталог CurseForge
- `src/main/modpacks.js` — установка сборок (.mrpack и CurseForge zip)
- `src/main/store.js` — настройки, профили, аккаунты
- `src/renderer/` — интерфейс (index.html, style.css, app.js, иконки)
- `komori.config.json` — ID приложения Microsoft и адрес сервера
